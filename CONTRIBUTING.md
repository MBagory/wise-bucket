# Contributing to Wise Bucket

Thank you for your interest! Wise Bucket is built in **small steps**; each one is tested and documented, and each design decision is recorded.

## Ground rules

- Be kind: see the [Code of Conduct](CODE_OF_CONDUCT.md).
- For anything bigger than a small fix, **open an issue first** so we can agree on the approach.
- **Design follows the [engineering tenets](docs/tenets.md)**, ranked: when two conflict, the higher one wins.
- **Documentation is part of the change.** A pull request that changes behaviour updates `docs/guide.md` or `docs/troubleshooting.md` (troubleshooting and FAQ) when useful, and `CHANGELOG.md`.

## Development setup

Requirements: Rust (the pinned toolchain in `rust-toolchain.toml` is installed automatically by rustup) and a C compiler: see [Build from source](docs/guide.md#build-from-source).

```sh
cargo build
cargo test --workspace
```

Tests generate their own fixtures; nothing is downloaded except by the sample tests (`--ignored`, run in CI).

To install your local build: `cargo reinstall` (alias in `.cargo/config.toml` for `cargo install --path crates/wb-server --locked --force`; `--force` replaces a release install), then reconnect the MCP server in your harness.

To see what an agent gets from Wise Bucket, run `evals/crosscheck.sh [format…]` on the sample recordings of each chosen format, or `evals/crosscheck.sh <folder>…` on your own recordings (needs Claude Code and `jq`; costs tokens, asks first). It extracts every recording into an empty store of its own, then, per format or folder, Claude compares what it finds through Wise Bucket with what it finds on its own from the raw files, and writes a report to `evals/reports/` (not versioned) to paste into a development session. `CC_MODEL` (default `sonnet`) and `CC_BUDGET` (USD per report, default 5) set the model and the cap.

### Branches

GitFlow ([ADR 0031](docs/decisions/0031-gitflow-and-semver.md)):

- `main`: released code only; every merge into it is tagged `vX.Y.Z`.
- `develop`: the default branch; open pull requests against it.
- `feature/<name>`: from `develop`, merged into `develop`.
- `release/X.Y.Z`: from `develop`, merged into `main`, then `main` merged back into `develop`.
- `hotfix/X.Y.Z`: from `main`, merged into `main`, then `main` merged back into `develop`.
- Pull requests into `main` use a merge commit, never squash or rebase.

### Versions

[Semantic Versioning](https://semver.org/spec/v2.0.0.html) of the MCP tools and their parameters, the SQL tables, columns and `stream()`, the CLI commands and flags, and the configuration keys and `WB_*` variables. Before 1.0: a breaking change or a new feature bumps MINOR, fixes only bump PATCH. A new `EXTRACTOR_VERSION` alone is not breaking.

### Releases

- **Cross-check first:** run `evals/crosscheck.sh` on every format and read the reports; each finding confirmed against the files becomes an assertion in `crates/wb-server/tests/samples.rs`, with the reference decoder's value.
- **App:** on `release/X.Y.Z` (or `hotfix/X.Y.Z`), bump `version` in the root `Cargo.toml` and in `CITATION.cff` (with `date-released`), move the `Unreleased` entries of `CHANGELOG.md` under `## [X.Y.Z] - YYYY-MM-DD` and add its link at the bottom. Merge the pull request into `main`, push a `vX.Y.Z` tag on the merge commit, and merge `main` back into `develop`. dist turns that section into the release notes, where only absolute links work. The `release` workflow (generated by [dist](https://github.com/axodotdev/cargo-dist) from `dist-workspace.toml`; regenerate it with `dist generate`) builds the binaries and the installer and publishes the GitHub release.
- **DataFusion, `parquet`, `re_ros_msg` and `rerun`** share one Arrow version: upgrade them together, and check with `cargo tree -p wb-data -i arrow-array` that only one Arrow remains ([ADR 0021](docs/decisions/0021-parquet-for-streams.md)).
- **Extraction output:** bump `EXTRACTOR_VERSION` in `crates/wb-data/src/lib.rs` whenever extracted streams change, `recording.json` included, even between releases: every recording is then extracted again, and no store keeps output another build wrote.

## Before opening a pull request

```sh
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo run -p wisebucket -- docs gen       # regenerate docs/reference/*
```

CI runs the same checks on Linux and macOS, plus `cargo deny`, link checking and spell checking.

## Conventions

- **Errors:** every user-facing error is a `WbError` with a stable code from `crates/wb-core/src/error.rs` and a documented fix. Adding a code means adding its title and fix there; `docs gen` renders `docs/reference/errors.md`, and a test fails if a code is undocumented.
- **Configuration keys:** documented in `KEYS` in `crates/wb-core/src/config.rs`, rendered to `docs/reference/configuration.md`.
- **Output:** human messages go to stderr; stdout is for data (`--json`) and, in `serve`, reserved for MCP messages.
- **No LLM calls, no network at runtime:** only `demo` downloads, always checksum-verified.
- **Metrics are SQL, not features:** the agent writes them, with no new tool or precomputed column ([ADR 0010](docs/decisions/0010-metrics-are-sql-written-by-the-agent.md), [ADR 0017](docs/decisions/0017-result-size-and-paging.md)). A recipe (`RECIPES` in `crates/wb-data/src/tables.rs`) is one line, and only for what the model cannot know: Wise Bucket's dialect or schema ([ADR 0036](docs/decisions/0036-recipes-only-for-the-dialect.md)). A test caps the length of the `sql` description and the agent instructions.
- **Formats:** a new format needs an external Rust crate that decodes it; our code only maps the crate's output to streams, with exact-value tests on a fixture ([ADR 0016](docs/decisions/0016-formats-need-an-external-rust-decoder.md)).
- **Tables:** the tables and columns the agent can query are documented in `TABLES` in `crates/wb-data/src/tables.rs`, rendered to `docs/reference/tables.md` and to the `sql` tool's description.
- **Design decisions:** a change of design comes with an [ADR](docs/decisions/README.md) in `docs/decisions/`. ADRs are never rewritten once released: a new one supersedes the old.
- **Tests:** acceptance tests live in `crates/wb-server/tests/` and drive the real binary with a real MCP client; format tests live in `crates/wb-data/tests/` and check exact values on generated fixtures.
- **Commits:** clear, imperative messages ("Add roots check command"). Sign off your commits (`git commit -s`) to certify the [Developer Certificate of Origin](https://developercertificate.org).
