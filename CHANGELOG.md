### Added

- **Every recording in your data roots is extracted into a store**: a decoded, columnar copy of its signals, one table per stream, with a common nanosecond time column `t` (plus `t_sensor` from `header.stamp`, and `message_bytes`). Wise Bucket trades disk space for query speed ([ADR 0012](docs/decisions/0012-trade-storage-for-query-speed.md)). Readable formats: ROS 2 bags (MCAP or SQLite `.db3`; Humble bags are decoded with bundled standard message definitions), MCAP files, PX4 ULog, MAVLink telemetry logs (`.tlog`, one stream per message, with `system_id` and `component_id`), CSV, JSON Lines, Parquet and Arrow IPC. A format ships only when an external Rust crate decodes it ([ADR 0016](docs/decisions/0016-formats-need-an-external-rust-decoder.md)). Images, point clouds, maps and video keep their timing and sizes only. ROS 1 bags are listed as `unsupported`.
- **Automatic, in the background:** while an agent session is open, new and changed recordings are found through file events and extracted, newest first, one at a time, in a low-priority child process: a file renamed into place (a finished download) at once, a file written in place once it has not changed for 5 seconds ([ADR 0018](docs/decisions/0018-extraction-on-file-events.md)). Several agent windows never extract the same file twice. A deleted recording stays queryable as `missing`. Extraction pauses below 10 GB of free disk space.
- **The `sql` tool** (and `wisebucket sql "<query>"`): read-only SQL over the tables `recordings` and `streams` and the function `stream('<name>' [, '<recording LIKE pattern>'])`, run by Apache DataFusion over Parquet files, with no database to install ([ADR 0011](docs/decisions/0011-no-database.md)). Nothing is computed in advance: rates, gaps, windows, percentiles and joins are written when a question needs them ([ADR 0010](docs/decisions/0010-metrics-are-sql-written-by-the-agent.md)). Queries are capped at 30 s and 1 GB; DDL, writes and file access are refused. A result holds about 60 KB of rows (or `limit` rows, `--limit` in the terminal), as arrays in the order of `columns`; when rows are cut, a `hint` says how to aggregate or fetch the next page. Recipes show how to plot (min, avg and max per time bin) and how to page by time window or by key ([ADR 0017](docs/decisions/0017-result-size-and-paging.md)).
- **The `rerun` tool** (and `wisebucket rerun "<query>"`): sends every row of a read-only query to a running Rerun viewer, with no size cap ([ADR 0019](docs/decisions/0019-send-query-results-to-rerun.md)). Each timestamp column (`t`, `t_sensor`) becomes a timeline, shown as durations when it counts from boot; each numeric or boolean column a scalar series at `<entity>/<column>`. All sends go to the Rerun recording `wisebucket`.
- **Abnormal and similar recordings:** recipes for a robust z-score of one value per recording against its peers, spikes inside a recording, and the recordings closest to a reference by distribution ([ADR 0020](docs/decisions/0020-abnormality-and-similarity-as-sql-recipes.md)).
- **The `server_info` tool:** the version, the store (recordings per status, size, paused), and each data root with its hardware and its candidate recordings by kind (each root's scan stops after 5 seconds). Declared read-only.
- **The `wisebucket` binary** (short alias `wbk`): the MCP server over stdio (`serve`) and the command-line tool, built on DataFusion and Parquet for instant analysis.
- `setup`: asks for your recording folders (or `--yes --root name=path`), downloads nothing, and prints how to register Wise Bucket once for your user (`claude mcp add --scope user …`, or a JSON entry for other agents).
- Data roots, user-wide ([ADR 0004](docs/decisions/0004-user-wide-only.md)): `roots add|list|remove|check`, the hardware they come from (`--hardware`), include and exclude globs (a rosbag2 folder is matched through its `metadata.yaml`), overlap and symlink checks, and candidate recordings counted by kind.
- Configuration: flags > `WB_*` environment variables > user configuration > defaults, with `config show --origin` and `config path`.
- `doctor`: checks the configuration, the state directory, the store, SQL and the data roots, with error codes and documentation links.
- `demo [FORMAT…] | --all | --list`: downloads public sample recordings (ROS 2 MCAP and SQLite bags, MCAP, PX4 ULog, ArduPilot DataFlash, MAVLink tlog, CAN ASC/BLF, MDF4, Parquet; six PX4 ULogs, to compare recordings; only formats an existing Rust crate can decode) from their upstream projects at pinned commits, verifies their SHA-256, and declares them as the `demo` data root. Nothing is redistributed by this repository. Downloads time out (30 s to connect, 60 s for the server to answer, 30 min per file) with `download_failed`.
- `completions <bash|zsh|fish|elvish|powershell>` prints a completion script for the name it is invoked as (`wisebucket` or `wbk`).
- Structured errors with stable codes and documented fixes; JSON errors, in tool results and `--json` output, include the absolute `docs_url`.
- CLI: colored status glyphs and `--help` (off when piped or with `NO_COLOR`), examples in `--help`, `--json` on `config`, `roots`, `sql` and `doctor`, with errors printed as `{"error": {…}}` on stderr.
- Documentation as plain Markdown: the README with Wise Bucket's principles, the user guide (with compatible [viewers](docs/guide.md#viewers)), troubleshooting and FAQ, generated references (CLI, configuration, errors, tables), [decision records](docs/decisions/README.md) with the list of possible features that replaces a roadmap, and privacy notes in `SECURITY.md`.
- Tests: acceptance tests drive the real binary through a real MCP client; format tests check exact values on generated fixtures; per-format sample tests (`cargo test -p wisebucket --test samples -- --ignored`) run in a dedicated CI job per format.
